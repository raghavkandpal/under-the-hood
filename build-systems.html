Build systems

Change one file in a big project and make, Bazel or your bundler rebuilds only what's affected, in the right order, using every CPU core. Underneath is a graph of "this depends on that", and an algorithm that has been around since 1962.

Click a source file (grey) to pretend you edited it. Orange = must rebuild. Each box shows its compile time.

The build, with unlimited parallel workers (red = critical path: the chain that sets the total time)

How it works

A dependency graph. Each output (an object file, a library, the app, the tests) lists what it's built from. Since nothing may depend on itself, even indirectly, it's a directed acyclic graph.

Topological order. To build, repeatedly pick anything whose inputs are all ready. That's Kahn's algorithm. Everything ready at the same moment forms a "wave" that can run in parallel, which is how make -j keeps all your cores busy.

Incremental builds. Editing a file dirties it and everything downstream of it, nothing else. Edit util.h and much of the project rebuilds. Edit test_util.c and only the tests do. Make compares file timestamps. Bazel and modern bundlers compare content hashes, so touching a file without changing it costs nothing.

The critical path. With enough cores, the build takes as long as its longest chain of dependencies, not the sum of everything. Speeding up anything off that path changes nothing. Speeding up the red bars does.

Cycles make an order impossible. Tick the box and the build fails with the loop it found, the same "circular dependency" error package managers and module bundlers report.
