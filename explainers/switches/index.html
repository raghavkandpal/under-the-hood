Switches and ARP

A switch learns which port each machine is on from the frames it sees. ARP turns an IP address into the MAC address a frame needs.

  • out

How it works

Learning. A switch starts with an empty table. Every frame that arrives tells it which port the sender is on, so it writes down source MAC and port. If it knows the destination it sends the frame out of that one port. If it does not, it floods: out of every port except the one the frame came in on. With an empty table, A's first frame to B reaches ports 2, 3 and 4, and B's reply goes out port 1 only, because A was learned from the first frame.

Forgetting. Entries age out. In this model an entry is dropped after 300 seconds with no frame from that host, and the next frame to it floods again. If B moves to port 3, frames to B keep going to port 2 until B sends something, because that is the only way the switch finds out.

Try it. On the Switch tab send A to B, then B to A, then A to B, and read the ports each time. Then wait and send again.

ARP. A frame carries a MAC address, but programs use IP addresses. To reach 10.0.0.2, A broadcasts an ARP request, "who has 10.0.0.2?". The request is flooded to every other port and only B answers, with a reply sent to A alone. A keeps the answer in its ARP cache, so the second packet to 10.0.0.2 needs no ARP frames.

Off the network. The router is on 10.0.0.254. For 203.0.113.5, which is outside 10.0.0.0/24, A asks ARP for the router's MAC and never for 203.0.113.5. The frame is addressed to the router's MAC, while the IP destination stays 203.0.113.5, and the router carries it on from there.

Loops. Floods do not stop by themselves. With two switches joined by two cables, a broadcast from A goes over both cables, and each copy is flooded out of the other cable, so 2 frames are still in flight after 100 steps and B has received 100 copies. Block one cable and the broadcast arrives once and stops. Spanning tree is the protocol that picks which cable to block.

One switch, one subnet and made-up MAC addresses; the 300-second timeout is this model's choice. Spanning tree itself, VLANs and ARP spoofing are left out.
