Data leakage

Here are 100 customers, 1,000 columns of random numbers, and a random yes/no label. There is nothing to learn. Yet one small change in the order of the steps gets a model to 80% accuracy on held-out data.


    

      
      
    

    
    

  


  
How it works

  
The test set is a promise. You hold some data back so you can estimate how the model will do on data it has never seen. That estimate is only honest if nothing about the held-out rows influenced any decision made during training. Leakage is any path by which they did, and it makes the score look better than the model really is.

  
Choosing features first. With 1,000 columns of noise, some will differ between the yes and no groups purely by chance. Picking the 20 most different columns using all rows means picking columns that happen to separate the test rows too. The model then “predicts” them, and the score says 80%. Pick them using the training rows only and the test rows get no say: the score falls back to a coin flip. The more columns you search, the stronger the illusion.

  
Try it. Run all three pipelines with 1,000 columns, then the leaky one with only 10 columns, then with 5,000.

  
Duplicates. If the same customer appears in both sets (two orders, two scans of the same patient, near-identical photos), the model has already seen the answer. Split by customer, not by row, and remove near-duplicates first.

  
Other leaks. Scaling or filling in missing values with averages computed on all the data. Tuning settings by checking the test score again and again, which slowly fits the test set (it's multiple testing in disguise). Features that are only known after the fact: “refund issued” predicts “customer complained” rather well. Random splits of time series, where the model trains on the future. The cure for all of them is the same: put every step that learns from data inside the training fold, which libraries like scikit-learn do with pipelines.

  
Simplified: a nearest-centroid classifier on 20 selected columns, a 70/30 split, and 20 duplicated rows. The effect is the same for any model, and grows when rows are few and columns many.
