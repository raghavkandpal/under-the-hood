Processes: fork, exec, wait

Every program you run is started the same odd way. A process makes an exact copy of itself, and the copy then replaces its own program with the new one. When it finishes, it lingers as a zombie until its parent asks how it went.

    
  
    

  
    How it works
    
  
    fork. The kernel duplicates the calling process: same program, same memory, same open files, a new process id. Both copies return from the same fork() call. The parent gets the child's pid back and the child gets 0, which is the only way each knows which one it is. Copying all of memory would be slow, so the kernel shares the pages and copies one only when either side writes to it (copy-on-write; see virtual memory).
    
  
    exec. The child then calls exec with a program path. The kernel throws away its memory and loads the new program, but the pid, the parent and the open files stay. That's how a shell's ls > out.txt works: after the fork, the child points its standard output at the file, then execs ls, which writes to “standard output” without knowing it's a file. Pipes are set up the same way.
    
  
    exit and wait. When a process exits, the kernel frees almost everything, but keeps a small entry with its exit status until the parent calls wait() to collect it. Until then it's a zombie. A parent that never waits leaks zombies, which is why servers that spawn helpers must reap them.
    
  
    Try it. Fork the shell, fork the child, then exit the child before the grandchild. Watch who becomes the grandchild's parent, and what happens when the grandchild exits.
    
  
    Orphans. If a parent exits first, its children are re-parented to process 1, init (systemd on most Linux systems), whose job includes waiting on every orphan so no zombie lingers. A process tree is a family history: everything descends from init.
    
  
    Simplified: no signals, no blocking (a wait with live children just reports it would block), and init reaps instantly. Linux's clone() generalises fork, and posix_spawn() combines fork and exec.
