Logistic regression

Will this student pass? A straight line through the data can't answer with a probability: it happily predicts 130% or −20%. Logistic regression bends the line's output through an S-curve, so every answer lands between 0 and 1, and fitting it is a few hundred small steps downhill.

How it works

A score, then a squash. The model computes a weighted sum, z = w₁ × hours studied + w₂ × hours slept + b, just like linear regression. Then it passes z through the sigmoid, 1 / (1 + e−z), which maps any number to between 0 and 1: z = 0 gives 50%, large positive z approaches 100%, large negative approaches 0%. The 50% line is where z = 0, a straight boundary; the shading shows the probability rising across it.

Log loss. A prediction is scored by how surprised it was by the truth: −log of the probability it gave the actual outcome. Saying 90% and being right costs 0.1; saying 99% and being wrong costs 4.6. Averaged over the data, this rewards being confident only when it's justified. Fitting means finding the weights with the lowest average loss.

Gradient descent. There's no formula for the best weights, but the slope of the loss is simple: for each student, (prediction − label) × their inputs. Step the weights a little against it and repeat. The loss is bowl-shaped for this model, so gradient descent always reaches the bottom.

Try it. Drag the overlap to zero and watch the shading sharpen, then add one failing student deep in the passing side.

Probabilities you can use. When the classes overlap, the output is calibrated: of the students it gives 70%, about 70% pass. That's what makes it useful for decisions, and why you pick the threshold separately (see ROC curves). When the groups separate perfectly, the loss keeps falling as the weights grow towards infinity, and the model becomes absurdly sure. A small penalty on large weights (L2 regularisation, on in this page) stops that. A single neuron in a neural network is exactly this model.

Simplified: two inputs, made-up students, and plain batch gradient descent for 1,500 steps. Real libraries use faster second-order optimisers.
