Tries vs suffix arrays

A trie finds words that start with what you typed. To find text that contains it anywhere, you need every suffix of the text in order, and there are two ways to store them: a tree of letters that grows quickly, or a plain array of start positions.

How it works

The suffix array. Write down every suffix of the text, sort them, and keep only where each one starts. For "banana" the sorted suffixes are a, ana, anana, banana, na, nana, so the array is [5, 3, 1, 0, 4, 2]. A second array, the LCP, records how many letters each suffix shares with the one above: [1, 3, 0, 0, 2]. Kasai’s algorithm fills it in a single linear pass.

Finding a pattern. Every occurrence of a pattern is the start of some suffix, and suffixes starting with the same letters sit next to each other. So two binary searches, one for each end of that block, find them all. Each search makes at most ⌈log2(n+1)⌉ comparisons, so a lookup costs at most 2⌈log2(n+1)⌉: 20 for n = 1,000. Each comparison reads up to as many letters as the pattern has.

Prefix versus anywhere. A trie of the words “database metadata update” answers “data” with one word, database, because only database starts with it. The suffix array answers with two places, the start of database and the middle of metadata. That difference is the reason to index suffixes.

The suffix trie. Put every suffix into a trie and any substring is a path from the root, one node per letter. The cost is size. A text has at most n(n+1)/2 substrings, and the trie needs a node for each distinct one: 15 for “banana”, so 16 nodes with the root. Subtracting the LCP total counts them without building the trie: 21 − 6 = 15. For a random 4-letter text of 1,000 letters the trie has about 496,000 nodes against 1,000 array entries, roughly 500 to one. Over the lengths 10 to 1,000 on the slider the ratio keeps growing.

The suffix tree. Most of those nodes sit in long chains with one child each. Merging each chain into one edge, as a radix tree does, leaves a suffix tree, which has fewer than 2n nodes. For “banana” that is 7 nodes, against 16 in the trie. With an end marker so that every suffix is a leaf, “banana$”, it is 11 against 23. It keeps the trie’s speed in linear space, but with more pointers per node than an array’s one integer per suffix, which is why practical tools often pick the array.

The longest repeated substring. Two copies of a substring begin two suffixes that share it, and sorting puts such suffixes next to each other, so the longest repeat is the largest LCP value. In “banana” that is 3, “ana”.

Try it. Pick terms and search “data”, then pick random and slide n from 10 up to 1,000 while watching the bars.

The suffix array here is built by sorting whole suffixes, which is fine for short texts but slow for large ones, where real tools use faster constructions. The trie sizes for the long random texts are counted by formula, checked against a real trie on shorter ones.
