Recommender systems

You've rated a few films. So has everyone else, and each person has seen only a handful. How can a site guess how much you'd like one you've never watched? By learning a hidden "taste" vector for every person and every film from the ratings that do exist.

How it works

The ratings table is mostly empty. Real services have millions of users and items, and each user rates a tiny fraction. The job is to fill in the blanks.

Assume taste has few dimensions. Give each person a short vector p ("likes sci-fi 0.9, likes drama 0.2") and each film a vector q ("is sci-fi 0.8, is drama 0.1"). Predict a rating as average + user bias + film bias + p · q. Nobody tells the model what the dimensions mean. It finds them by nudging every vector to reduce the error on known ratings, which is gradient descent again.

Collaborative filtering. If Ana and Bo agreed on everything they both watched, Ana's high rating for a film Bo hasn't seen pushes Bo's predicted rating up. In the taste space, the films separate into groups without ever being told their genres.

Limits. A brand-new user or film has no ratings, so no vector (the cold-start problem), so real systems blend in content features. Optimising only for predicted ratings also tends to recommend what's already popular. This technique was the core of the winning Netflix Prize entries (2006–2009).
