Branch prediction

The same loop over the same numbers can run several times faster if the numbers are sorted first. Nothing about the work changes. The processor just stops guessing wrong about one if.

How it works

Pipelines guess. A modern core works on a dozen or more instructions at once, each at a different stage, like an assembly line. When it reaches a branch, the instructions after it are already needed, but whether the condition is true won't be known for several cycles. Rather than wait, the processor guesses and carries on. A right guess costs nothing. A wrong one means throwing away the work in flight and restarting, around 15 cycles.

The sorted-array trick. Take if (x >= 128) sum += x over random bytes. Unsorted, the branch is a coin toss and no predictor beats 50%. Sorted, it's false for the first half and true for the rest, so after one wrong guess at the switch every guess is right. With 15 cycles a miss, that's roughly 8.5 cycles per element against 1: the same instructions, several times faster.

Counters. The simplest real predictor remembers which way the branch went last time. A 2-bit counter needs two wrong guesses in a row before it changes its mind. That matters for loops: at the end of each loop the exit branch falls through once, and a 1-bit predictor then gets the next loop's first iteration wrong as well. A 2-bit counter misses only the exit.

Try it. On the alternating pattern, compare the 1-bit and 2-bit counters with the history predictor.

History. Real predictors also look at the last several outcomes and keep a separate counter for each recent pattern, so they learn repeating sequences like alternation, or a loop that always runs 8 times. Modern designs (TAGE, perceptron predictors) combine many history lengths and get well over 95% right on typical code.

Avoiding the branch. Compilers can sometimes replace a branch with a conditional move, or with arithmetic like sum += x & -(x >= 128), which has nothing to predict. Code that sorts or groups data so similar items come together helps the predictor and the cache at the same time.

Simplified: one branch in isolation, one cycle per element otherwise, and a 15-cycle penalty. Real predictors share tables between branches, and the speculative work they throw away was the root of the Spectre attacks.
