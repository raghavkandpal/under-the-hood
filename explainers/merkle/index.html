Merkle trees

How does Git know two repositories are identical without comparing every file? How does BitTorrent check a piece from a stranger, or a blockchain prove one transaction is in a block? They hash the data in a tree, so a single short fingerprint vouches for everything below it.

Blocks:

The data blocks

Three superpowers from one idea

Build: hash each block. Then hash pairs of hashes, then pairs of those, up to a single root hash. Change one byte anywhere and its leaf hash changes, so its parent changes, and so on up to the root. The root is a fingerprint of everything.

1. Detect and locate changes cheaply. Two machines compare roots. If they match, everything matches. If not, they compare the two children and only descend where the hashes differ. Finding one changed block among a million takes about 40 comparisons instead of a million. Git, Cassandra and Dynamo-style databases use this to sync replicas, and ZFS uses it to catch disk corruption.

2. Prove membership with a few hashes. To prove block 5 is part of a tree whose root you trust, I hand you block 5 plus one sibling hash per level (the blue nodes). You hash your way up and check you land on the root. That's log₂(n) hashes, 20 for a million blocks. Certificate Transparency logs, Bitcoin light clients and BitTorrent v2 rely on this.

3. Tamper evidence. Since every hash depends on everything beneath it, nobody can change the history under a published root without changing the root itself. This is the core of Git's commit chain and of every blockchain.

Hashes here are SHA-1 shown as 6 hex characters. Leaves and internal nodes are hashed with different prefixes so one can't be passed off as the other. An odd node at the end of a level is carried up unchanged.
