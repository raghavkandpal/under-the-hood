CDNs & edge caching

A round trip across the Pacific takes over 80 ms even through a perfectly straight cable, and real routes take well over 100. No amount of engineering makes light faster. So big websites don't serve you from one data centre. They copy their files to hundreds of edge servers around the world and answer from the one closest to you. That's a content delivery network.

How it works

Distance is latency. Light in glass covers about 200 km per millisecond, and real cable routes are longer than straight lines. A user in Sydney fetching from a server in Virginia waits well over 200 ms per round trip before the server has done anything. Opening a page takes several round trips (DNS, TCP, TLS, then the request), so that becomes a second or more.

Edge caches. A CDN puts servers in dozens or hundreds of cities and routes each user to a nearby one, usually through DNS or anycast. If that edge has a fresh copy (a hit), it answers in a few milliseconds. If not (a miss), it fetches from the origin once, keeps a copy for the time-to-live set by the cache headers, and serves everyone nearby from it.

Trade-offs. Longer TTLs mean more hits, but stale content lingers after you publish. More edges put users closer, but each edge warms its cache separately, so the hit rate per edge falls (compare 3 and 8 edges). Popular content caches well and the long tail doesn't. Misses are why the slowest requests (p95) barely improve even when the typical one gets much faster.

The thundering herd. When content changes, caches are purged, and suddenly every edge misses on every popular file at once. Without care, each of those misses becomes its own origin request. Request coalescing (collapsed forwarding) lets one miss per object per edge go to the origin while everyone else waits for it. The busier the site, the bigger the difference.

Simplified: latency is one round trip, and every request is one small file. Real CDNs also stack caches (edge → regional shield → origin), terminate TLS at the edge, and run code there. Related: consistent hashing, which spreads content across servers inside each location.
