What each layer buys you

Plaintext is game over. No attack is even needed.

Hashing is one-way, but the attacker doesn't reverse it. They hash guesses and compare. Without a salt, one hash of "sunshine" matches every user with that password (see the red rows), and the attacker can hash the whole dictionary once, or download a precomputed table, then look everyone up instantly.

A salt is a random value stored next to each hash and mixed in before hashing. It's not secret. Its job is to make every user's hash unique, so each guess has to be redone per user and precomputed tables become useless.

A slow hash is the real defence. SHA-256 was built for speed, and a modern GPU computes billions per second. Password-hashing functions (PBKDF2, bcrypt, scrypt, Argon2) are deliberately expensive, tuned so a login takes milliseconds but an attacker's billions of guesses take years. Argon2 and scrypt also use lots of memory, which blunts GPUs.

And still: no hashing scheme saves a password that's on the list. "dragon1" falls in every mode, just more slowly. The long passphrase never falls. Length and unpredictability beat clever substitutions, and a password manager beats both.

Toy scale: a ~100-word dictionary where real attackers use billions of candidates plus mutation rules. The GPU figure is a rough order of magnitude for unsalted SHA-256 on a single high-end card. The browser's PBKDF2 is the real algorithm, and real deployments use 600,000+ iterations or Argon2.
