Three-way merge

You and a teammate both edited the same file. Comparing your two versions alone can't tell who added a line and who deleted one. Git also looks at the version you both started from, and that's what lets most merges happen without asking you anything.

How it works

  
Why two versions aren't enough. Suppose your copy has a line that theirs lacks. Did you add it, or did they delete it? Comparing the two can't say, so a two-way merge would have to ask about every difference. The common ancestor, the commit both branches started from, answers it: if the ancestor had the line, they deleted it; if not, you added it.

  
The algorithm. Diff the ancestor against each side separately, which turns each side into a list of changes to particular ancestor lines. Walk the ancestor from top to bottom. Lines neither side touched are kept. A stretch only one side changed takes that side's version. A stretch both changed the same way is taken once. Only when both sides changed the same lines differently is there a real conflict, and git writes both versions between <<<<<<<, ======= and >>>>>>> markers for you to resolve.

  
Try it. In the clean preset, delete a line in ours and add one at the end of theirs. Then change the same line differently in both.

  
Finding the ancestor. Git finds it automatically: the merge base is the most recent commit reachable from both branches. That's why merging often stays painless: each merge records a new common point, so the next merge only compares changes since then. A long-lived branch drifts further from its base, and more of its changes overlap.

  
What it can't know. The merge works line by line and knows nothing about meaning. Two clean changes can still break the program together: one side renames a function while the other adds a new call to the old name. No conflict appears, and the tests are what catch it.

  
Simplified: git also marks a conflict when the two sides' changes are next to each other without overlapping, and offers smarter strategies (patience and histogram diffs, renames, recursive merge bases) on top of this core.
