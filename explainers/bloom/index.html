Bloom filters

How does a browser check a URL against millions of known-bad sites without downloading a huge list? It uses a Bloom filter, a row of bits that answers "definitely not" or "probably yes" in a tiny fraction of the space.

How it works

Adding an item runs it through k hash functions. Each one names a bit, and all k bits are switched on. The item itself is never stored.

Checking runs the same hashes. If any of those bits is off, the item was definitely never added, because adding it would have set that bit. If all are on, it was probably added, though the bits might have been set by other items. That's a false positive. There are never false negatives.

The trade-off. More bits mean fewer collisions. More hash functions catch more non-members, but each item also fills the array faster. The best k is about (m/n)·ln 2. At 10 bits per item with 7 hashes, you get about 1% false positives no matter how long the items are.

Where it's used: databases skip disk reads for keys that can't be there (Cassandra, RocksDB, Bigtable). CDNs avoid caching one-hit wonders. Browsers have used them for Safe Browsing. In each case, "probably yes" triggers an exact but expensive check, and "definitely not" saves the work.

Try it: with 64 bits and k = 3, add 25 random items and run the 1,000-non-member test. Now try k = 1 and k = 8 with the same items, and see which does worse and why. Deleting is the other catch. You can't clear a bit, because other items may rely on it.
