How linkers work

A compiler turns each source file into an object file that has holes where it calls code defined somewhere else. The linker pairs every use of a name with one definition, lays the pieces out in memory, and fills in the holes.

How it works

Names pair up. In this model there are nine toy object files. main.o defines main and calls area and print. geom.o defines area, io.o defines print, and fast.o is a second definition of area. Alone, main.o gets two undefined-reference errors. With geom.o and io.o it links. Add fast.o and the link fails with a multiple-definition error naming geom.o and fast.o.

Archives are scanned in order. libgeom.a holds 5 members: str.o, shape.o, fmt.o, sq.o and log.o. GNU-style linkers read inputs left to right and take an archive member only if it defines something that is undefined at that point. Here main.o needs area, which shape.o defines, and shape.o calls square, which sq.o defines. The output contains those 2 members and the other 3 are left out. Put the archive before main.o and nothing is undefined yet when it is read, so it contributes nothing and the link fails with an undefined reference to area. Other linkers handle the order differently.

Relocation fills the holes. Code is placed from address 0x1000 in command-line order. The sizes in this model are 32 bytes for main.o, 24 for geom.o and shape.o, 16 for io.o and 8 for sq.o. Each call has a 4-byte field and an addend A of −4. For a PC-relative call the linker writes S + A − P, where S is the address of the target and P is the address of the field. In Eli Bendersky's worked example, S = 0x0012e49c, A = −4 and P = 0x0012e4b4 give 0xffffffe4, which is −0x1c as a signed 32-bit number.

Moving the callee. Linking main.o io.o geom.o puts area at 0x1030 and the patched field for it is 0x00000024. Insert sq.o before geom.o and area moves to 0x1038, so that field becomes 0x0000002c. The field for print stays 0x00000008, because io.o did not move.

Try it. Compare "Archive after" and "Archive first", then "Callee moved" and "Three objects".

This is static linking of invented object files; dynamic linking, the PLT and GOT, position-independent code, weak symbols, linker scripts and real ELF layouts are left out. Archive rules in this model follow GNU-style linkers and the cited articles, and other linkers differ.
