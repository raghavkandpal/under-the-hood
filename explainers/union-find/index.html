Union-find

"Are these two computers on the same network?" "Are these two pixels part of the same blob?" Union-find answers "are A and B connected?" while you keep adding connections, in practically constant time, using two tiny tricks.

1. Sets as trees

Click two items to union them, or one twice to find its root

2. Using it: Kruskal's minimum spanning tree

Connect every grid point as cheaply as possible: take edges cheapest-first, and skip any edge whose ends are already connected, because it would only make a loop. Union-find answers that question instantly.

How it works

Each set is a tree, and each item points to a parent. The root represents the whole set. find(x) follows parents up to the root. Two items are connected exactly when they have the same root. union(a, b) hangs one root under the other.

The danger is tall trees. Union things in an unlucky order without care and you build a long chain, so every find walks the whole thing. Untick both boxes and press "Worst case".

Trick 1: union by rank. Always hang the shorter tree under the taller one, so height grows only when two equal trees merge. Height then stays under log₂(n). Trick 2: path compression. After a find, point every node you passed straight at the root, so the next find is one hop. Together they make operations take α(n) time, the inverse Ackermann function, which is at most 4 for any input that could fit in the universe.

Also used for image segmentation, network connectivity, percolation simulations, type inference (unification) and the "same account?" grouping in fraud detection.
