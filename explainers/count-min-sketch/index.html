Count-min sketch

Which search terms are trending right now? Counting every distinct term exactly needs a table as big as the vocabulary. A count-min sketch keeps a small fixed grid of counters instead, and its answers are never too low.

How it works

A grid of counters. The sketch has d rows of w counters, and one hash function per row. To count an item, hash it once per row and add one to the counter it lands on in each row. To ask how often you've seen it, look up the same d counters and take the smallest.

Why the minimum. Every counter an item touches holds its true count plus the counts of whatever other items hashed to the same place. Collisions only ever add, so each counter overcounts or is exact, and the smallest one is the closest. An item has to collide badly in every row at once to get a bad estimate.

The guarantee. With width w, each estimate exceeds the truth by at most about e/w of the whole stream, with probability at least 1 − e−d. Width controls how big the error can be, and depth how often it happens. Memory is w × d counters however many distinct items there are.

Try it. Shrink the width until the long-tail item looks popular, then add rows and watch its estimate fall back.

Where it's used. The error is a fraction of the total, so it's small next to popular items and large next to rare ones. That's exactly right for finding heavy hitters: trending topics, the busiest IP addresses in a flood, hot keys in a cache. Like a Bloom filter, it trades exactness for a fixed, tiny footprint, and two sketches of the same shape merge by adding their counters.

Simplified: one stream of 50,000 events over 5,000 items, with popularity following a power law. Variants subtract an estimate of the noise, or update only the smallest counters (conservative update) to cut overcounting further.
