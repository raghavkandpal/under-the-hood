Coverage-guided fuzzing

Throw random bytes at a parser and you'll mostly test its first if. A coverage-guided fuzzer watches which branches each input reaches, keeps the inputs that got somewhere new, and builds on them, one byte of progress at a time.

if (len < 5) return
if (b[0] != 'F') return
if (b[1] != 'U') return
if (b[2] != 'Z') return
if (b[3] != '!') return
if (b[4] > 200) crash()

How it works

Random isn't enough. To reach the crash, an input needs four exact bytes in a row, about a 1 in 4 billion chance for random data, and then a large fifth byte. A random fuzzer running 20,000 inputs gets past the length check and almost never past the first letter. Real bugs hide behind exactly this kind of check: magic numbers, checksums, version fields, keywords.

Coverage as a signal. The program is compiled with lightweight instrumentation that records which branches each run took. An input that reaches a branch no earlier input did is interesting, so it joins the corpus. New inputs are made by mutating corpus entries: overwrite a byte, insert or delete one, flip a bit. The fuzzer climbs one check at a time, because getting the first letter right is rewarded before anyone knows about the second.

Deterministic, then random. Like AFL, this fuzzer gives each new corpus entry a deterministic pass, trying every value at every byte position, before falling back to random edits (“havoc”). Each new letter then costs at most 256 tries per byte position, and the whole bug falls in two or three thousand runs.

Try it. Start from the two-byte input and see where the guided fuzzer gets stuck. Nothing between two and five bytes reaches a new branch, so nothing is kept.

Plateaus. Coverage only helps when partial progress shows up as a new branch. A length check, a checksum over the whole input, or a 4-byte comparison compiled into one instruction gives no foothold. Real fuzzers split comparisons into byte-by-byte checks, mine constants from the binary into a dictionary, and start from a seed corpus of valid files. libFuzzer, AFL++ and Google's OSS-Fuzz, which has found tens of thousands of bugs in open-source projects, all work this way.

Simplified: a target with six checks, one mutation per run, and no crash triage or input minimisation. Coverage here is per branch; real tools also count how many times each edge was taken.
