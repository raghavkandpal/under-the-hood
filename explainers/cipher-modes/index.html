Block cipher modes

A block cipher like AES encrypts exactly one small block at a time. Real messages are longer, so a mode decides how the blocks are chained together. Pick the wrong mode and an encrypted image still shows its picture, even though every block is perfectly encrypted.

How it works

ECB (electronic codebook) encrypts each block independently. Same key plus same block always gives the same ciphertext, so repeated plaintext stays repeated: big areas of one colour come out as one repeated pattern, and the outline survives. Real AES uses 16-byte blocks, but whole images, database fields and protocol headers repeat at that size too.

CBC (cipher block chaining) XORs each block with the previous ciphertext block before encrypting, starting from a random IV. Every block now depends on everything before it, so repeats vanish. A flipped ciphertext bit scrambles its own block and flips the same bit in the next one, which is predictable enough that attackers have exploited it.

CTR (counter) encrypts the numbers nonce+0, nonce+1, … to make a stream of random-looking bytes, then XORs that with the message. Blocks are independent, so it's parallel and fast. A flipped bit flips exactly one bit of the output, so you need a separate integrity check, a MAC, to notice tampering.

The nonce rule. In CTR, reusing a nonce with the same key reuses the keystream, and XORing two ciphertexts cancels it out, leaving plaintext A ⊕ plaintext B. Both outlines appear. Real-world breaks of Wi-Fi encryption (WEP) and several messaging apps came from exactly this.

Modern practice is authenticated encryption: AES-GCM or ChaCha20-Poly1305 combine CTR-style encryption with a tag that detects any tampering, as used in TLS. The cipher here is a toy 16-bit Feistel network so that one pixel pair is one block. Don't use it for anything.
