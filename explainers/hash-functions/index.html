Hash functions

A cryptographic hash turns any input, a password or an entire movie, into a short fixed-size fingerprint. Change one letter and the fingerprint becomes unrecognisable. Yet fingerprints still collide much sooner than intuition says, thanks to the birthday paradox.

What's going on

What a good hash promises. It's quick to compute, but you can't run it backwards to find an input for a given hash (preimage resistance), and you can't find two inputs with the same hash (collision resistance). The avalanche effect is a symptom: each output bit should flip with probability ½ whenever anything in the input changes, so the output reveals nothing about how similar two inputs were.

Collisions come at √N, not N. With N possible hashes you'd think you need about N tries to hit a repeat. But every new value can collide with every earlier one, so the number of pairs grows like n². A repeat becomes likely after only about √N values. For a 20-bit hash (a million values) that's around a thousand tries, and the hunt above usually finds one in a blink.

Why output size matters. A b-bit hash only gives about b/2 bits of collision resistance. SHA-1's 160 bits mean about 2⁸⁰ work by brute force, and cryptographers found shortcuts well below that. A real SHA-1 collision was published in 2017, which is why it's retired for security. SHA-256 gives 2¹²⁸, far beyond any computer.
