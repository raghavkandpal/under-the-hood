Cross-site scripting

A comment box that shows what people typed. If the page pastes that text straight into its HTML, a comment can contain code, and the code runs in every visitor's browser with their login.


    

    

  


  
How it works

  
Data becomes code. HTML mixes content and instructions in one string. If a page builds that string by gluing in user text, the browser can't tell which parts the developer wrote, exactly like SQL injection. A script injected this way runs as the site itself: it can read the page, send requests with the visitor's cookies, or rewrite the login form.

  
Escaping. Replace the five characters that mean something in HTML (& < > " ') with entities like &lt;. The browser then shows them as text. That stops a <script> tag, and plain comments like “Tom & Jerry <3” still display correctly.

  
Context matters. Escaping is only right for text between tags. Inside an unquoted attribute, a space is enough to start a new attribute, and none of the escaped characters are needed to write onmouseover=…. Inside a link, javascript: URLs need no special characters at all. Each place needs its own rule: quote every attribute, and allow only http and https links.

  
Try it. Pick the attribute context and the handler payload, then switch from “Escape” to “By context”. Then do the same for the javascript: link.

  
Let the framework do it. Template engines and frameworks such as React escape by default, per context, so the safe path is the easy one. The holes are the escape hatches: innerHTML, dangerouslySetInnerHTML, building URLs from user input. If you must allow some HTML, run it through a sanitiser that keeps an allowlist of tags.

  
Defence in depth. A Content Security Policy header such as script-src 'self' tells the browser to refuse inline scripts, event-handler attributes and javascript: URLs, so even a missed escape doesn't run. Marking session cookies HttpOnly keeps scripts from reading them.

  
Simplified: the check looks for script tags, event attributes and javascript: links in the generated HTML, nothing is ever rendered, and the payloads are harmless alerts. Real attacks also use encoded characters, SVG and CSS. See OWASP's cheat sheet below.
