Transactions: all or nothing

Moving 30 from Alice to Bob takes two UPDATE statements, and the machine can die between them. A transaction makes the pair succeed or vanish together.

    How it works

    Autocommit. Outside a transaction every statement is its own transaction: it takes effect the moment it finishes. The debit commits, the machine dies, and after the restart Alice has 70 and Bob 50. The 30 is gone and the total is 120, not 150. Drag the crash point to the gap between the two statements.

    A transaction. BEGIN groups the statements, and nothing counts until COMMIT. SQLite does it with a rollback journal: before it changes the database file it copies the original value into a journal file. COMMIT deletes the journal, and that deletion is the moment the transfer happens. If the machine restarts and finds a journal, it is "hot", so the engine copies the originals back. Try every crash point: the table comes back as (100, 50) until the commit and (70, 80) after it, and the total is always 150.

    ROLLBACK. You can undo on purpose too. Choose ROLLBACK after both updates and the originals are restored, (100, 50), exactly as if nothing had run. The same thing happens when a statement fails.

    Try it: pick "120, Bob first". The credit to Bob succeeds, then the debit breaks CHECK balance >= 0. In a transaction the credit is undone and the table is (100, 50). In autocommit the credit stays: Bob has 170 and the total is 270, money from nowhere.

    What others see. Another session never reads the half-done state. Before COMMIT it reads (100, 50), after it (70, 80), and it never reads (70, 50). Under autocommit it can read (70, 50), between the statements. How databases hide uncommitted work from several concurrent sessions is the subject of isolation and MVCC; how real engines log changes so they can also redo committed ones is write-ahead logging.

    Simplified: each UPDATE is a single atomic write, the journal holds one value per row, and the other session reads the old values from the journal (real SQLite makes it wait). Locks, savepoints and fsync are left out.
