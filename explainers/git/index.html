Git internals

Under the commands, Git is a small database of four things: blobs (file contents), trees (directories), commits (snapshots plus history), and refs (movable name tags). Run real-looking commands and watch them appear.

Things worth noticing

  
    
    
  • The name is the content. An object's ID is the SHA-1 of its bytes. Two files with the same text are one blob. Change one character and you get a new blob, a new tree above it, and a new commit.
    • 
    
  • Commits are snapshots, not diffs. Every commit points to a complete tree. Unchanged files are cheap because the new tree just points at the same old blobs.
    • 
    
  • A branch is a 41-byte file. main is just a pointer to a commit. Branching copies a pointer, and committing moves it forward.
    • 
    
  • HEAD is "where you are". It usually names a branch, which names a commit.
    • 
    
  • git add writes objects. The blob is created when you stage, not when you commit. Stage, edit and stage again, and the first blob becomes unreachable garbage.
    • 
  

  
These hashes are real. git hash-object on the same file content gives the same blob ID here as on your machine. Commit IDs also depend on author and time, which this page fixes so they're reproducible. Simplifications: one author, merges are per-file (no line-level merging), no packfiles, no rebase.
