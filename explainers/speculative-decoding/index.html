Speculative decoding

A big language model writes one token per pass, and each pass reads billions of weights from memory, mostly waiting rather than computing. Checking five tokens costs about the same as producing one. So let a small, fast model guess the next few tokens, and have the big one check all the guesses at once. Same output, often 2–3× faster.

How it works

Why it's free to check. Generating text is limited by memory bandwidth: every token requires streaming the whole model's weights from GPU memory (see the KV cache). Feeding the big model 5 candidate tokens at once reads the weights once and scores all 5 positions in parallel, so it costs barely more than scoring 1.

The round. The draft model, perhaps 50× smaller, proposes k tokens one after another. The big model runs once over all of them. Going left to right, each guess is accepted with probability min(1, p/q), where p is the big model's probability for that token and q the draft's. At the first rejection, the big model picks a replacement from the probability the draft under-weighted (p − q, wherever that's positive), and the round ends. If all k pass, the same big pass also provides one bonus token.

Exact, not approximate. That accept/replace rule is built so that every token's probability is exactly what the big model alone would give, however bad the draft. The bars in the last panel agree. A bad draft only costs speed, never quality.

Tuning. More guesses per round helps only while they keep being accepted: with acceptance rate a, a round yields (1 − ak+1)/(1 − a) tokens on average, while each guess costs a draft pass. Lower the quality or raise the draft cost and the best k shrinks, sometimes to “don't bother”.

The two “models” are tiny word-pair tables so every probability is visible. Real systems draft with a small sibling model, extra prediction heads (Medusa), or text copied from the prompt, a big win when editing code.
