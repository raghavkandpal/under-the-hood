How the shell finds a command

A command name is not a file path. The shell checks its own functions and builtins first, then walks the directories in PATH, and remembers what it found.

        How it works

        The order. Before any of this, the shell has already done its expansions. In bash, a name without a slash is looked up as a function, then a builtin, then in the hash table, then in each PATH directory from left to right. In this model, ls is a function, so it runs instead of /usr/bin/ls, and cd is a builtin. For both, 0 directories are searched.

        PATH. In this model, python exists in /usr/local/bin and /usr/bin. With PATH /home/me/bin:/usr/local/bin:/usr/bin the shell checks 2 directories and runs /usr/local/bin/python. Put /usr/bin first and it checks 1 and runs /usr/bin/python. The first match wins, so the order of PATH is the order of preference.

        Slashes and the current directory. In this model, deploy exists only in the current directory, /home/me/project. Typed as deploy, it is looked for in all 3 PATH directories, not found, and the status is 127. Typed as ./deploy, the name has a slash, so PATH is not searched at all, and it runs. An empty PATH entry, or ., means the current directory, so a trailing colon, as in /usr/bin:, makes plain deploy work after 2 directories. That is also why a stray colon in PATH is a risk: whatever directory you are in becomes a place where commands are found.

        Skipped files. In this model, /home/me/bin/tool has no executable bit. The search skips it and runs /usr/bin/tool after checking 3 directories. If it were the only tool on PATH, nothing would run and the status would be 126, permission denied, instead of 127.

        The hash table. After a command is found through PATH, bash remembers where. The next run asks the table first and searches 0 directories. In this model, adding /home/me/bin/python after python has run changes nothing: the remembered /usr/local/bin/python still runs. hash -r empties the table, and the next lookup finds the new file after 1 directory. Assigning PATH empties the table too.

        Try it: run python, add ~/bin/python, and watch the lookup keep the old file. Then press hash -r.
