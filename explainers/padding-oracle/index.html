Padding oracle attacks

A server that only says whether the padding of a message was valid, and nothing else, still leaks the whole message: the attacker forges the previous block, watches the yes or no, and reads the plaintext one byte at a time without the key.

How it works

Padding. CBC needs whole blocks, so the sender pads the message: k − (length mod k) bytes, each holding that count. In this model the block is k = 2 bytes, so a 7-byte message gets one 01 and an 8-byte message gets a whole extra block 02 02. A block ending 01 02 is invalid. The receiver strips the padding, and many servers answer differently when it is wrong. RFC 5652 defines the rule.

The lever. CBC decrypts a block, then XORs the result with the previous ciphertext block (the IV for the first). So XORing a value d into byte j of that previous block XORs d into byte j of the plaintext, and the attacker controls the previous block. The attacker sends a forged previous block with the one target block and tries all 256 values for its last byte. When the server says the padding is valid, the plaintext ended in 01, so the unknown decrypted byte is the guess XOR 1 and the real plaintext byte follows by XORing with the true previous block.

The rest. Next the attacker forces the last byte to 02 and tries all 256 values for the byte before it. Only 02 02 is valid, which reveals that byte too. One check query per block rules out the lucky case where the first byte already read 02 and 02 02 passed instead of 01. That is at most 256 guesses per byte plus one check per block, about 128 per byte on average. Black and Urtubia put the cost at about 128 queries per byte for real ciphers. In this model the default message takes 2,092 queries for its 16 bytes, about 131 per byte, and each new IV gives a different count around that average. The IV travels with the message, so the first block falls too.

The fix. Add a MAC over the IV and ciphertext and check it before decrypting. Every forged request now fails the MAC, so all 256 guesses get the same answer and the attacker recovers nothing. This is why Black and Urtubia argued for authenticated encryption, and what GCM does.

Try it: switch to CBC + MAC, then back, and compare the answers seen and the bytes recovered. Type an 8-byte message and see the extra block.

The blocks here are 2 bytes and the cipher is a toy, not secure; real AES blocks are 16 bytes, so real padding is 1 to 16 bytes and the maths is the same per byte. The MAC here is HMAC-SHA1 with a key derived from the cipher key, for teaching only.
