Proof of work

How does a blockchain stop someone from rewriting history? It makes every block expensive to create. You have to find a number that, hashed with the block, gives a hash starting with zeros, and the only way is to guess billions of times. Here's a real one, using your browser's SHA-256.

Edit any block's data. Its hash changes, so it no longer starts with enough zeros, and the next block's "previous hash" no longer matches. Everything after it turns red.

How it works

A block holds some data, the hash of the previous block, and a nonce, a number the miner is free to change. Its hash is SHA-256 of all three. Change any character and the hash changes completely and unpredictably.

The puzzle. The block only counts if its hash starts with a certain number of zeros. Since hashes are unpredictable, the only strategy is to try nonce 0, 1, 2… Each extra hex zero makes it 16 times harder on average. Checking an answer takes a single hash, so work is expensive to do and cheap to verify.

Why history becomes hard to rewrite. To alter an old block you must redo its work, which changes its hash, which breaks the next block's link, so you must redo that one's work too, and every block after it, faster than the rest of the network keeps adding new ones. With enough honest computing power, that race can't be won. Bitcoin's network collectively computes hundreds of quintillions of hashes per second.

The cost is the point, and the problem. Security comes from burning electricity, which is why many newer blockchains use proof of stake instead. The hash-chaining idea itself, with each record committing to the one before, is the same one Git and Merkle trees use without any mining.

Toy chain: the hash covers "previous hash | data | nonce" as text. Real Bitcoin hashes a binary header twice with SHA-256 and compares against a numeric target rather than counting zeros.
