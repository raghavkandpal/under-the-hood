UTF-8 & Unicode

What looks like one character to you can be one byte or seventeen, one "character" to Python and four to JavaScript. Unicode gives every character a number. UTF-8 is the clever way almost the entire web turns those numbers into bytes.

What's going on

Code points. Unicode assigns every character a number: A is U+0041, é is U+00E9, 👍 is U+1F44D. There's room for 1.1 million of them, and about 150,000 are assigned so far.

UTF-8 stores each number in 1 to 4 bytes. Plain ASCII stays one byte and unchanged, so old English text is already valid UTF-8, which is a big reason it won. Accented Latin, Greek and Cyrillic take 2 bytes, most Chinese and Japanese 3, and emoji 4.

Characters aren't code points. "👍🏽" is a thumbs-up plus a skin-tone modifier: two code points, one character. The family emoji is several people glued together by invisible zero-width joiners. Flags are pairs of "regional indicator" letters. And é can be one code point or e plus a combining accent, which look identical but compare unequal unless you normalise the text.

Why JavaScript says "👍".length === 2. JavaScript, Java and Windows use UTF-16 internally. Code points above U+FFFF need two 16-bit "surrogate" units, and .length counts units. Truncating a string by .length can slice an emoji in half.

Character boundaries come from your browser's Intl.Segmenter. The UTF-8 encoder and decoder on this page are written by hand and tested against the built-in TextEncoder and TextDecoder.
