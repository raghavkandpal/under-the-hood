Passkeys

A passkey replaces the password and the typed code with a key pair. Your device keeps the private key, the site keeps the public one, and every login signs a fresh challenge for the exact site you are on.

How it works

Registration. The device makes a key pair for one site and sends only the public key. When the site's table of users is stolen, the thief gets public keys, which can verify a signature but not make one. An assertion signed with any other key fails against the stored one. There is nothing to crack, reuse or leak (this page uses the toy RSA from digital signatures; real passkeys use elliptic curves).

Logging in. The site sends a random challenge. The device signs it together with the site's origin and a counter, and the site checks the challenge, the origin, the site ID and the signature (Web Authentication §7.2). A challenge is spent the first time it is looked up, so a captured assertion replayed for a second login fails.

Try it. Pick the fake site, sign in, and compare the passkey tile with the typed code tile. Then pick the real site, sign in, and press Replay it.

Phishing. A typed code is only a number. Type it into examp1e.test and the attacker can pass it to the real site within its 30 seconds, and it is accepted. A passkey assertion carries the origin the browser saw, https://examp1e.test, inside the signed data, so the real site rejects it. The browser also never offers the credential there in the first place.

Which sites get the key. A credential belongs to an RP ID such as example.com. A page may use it when its host equals the RP ID or ends in a dot and the RP ID, so login.example.com is offered the key and example.com.evil.test and examp1e.test are not (§5.11).

The counter. Each device increases a signature counter on every login. If the site sees a counter that has not risen above the stored one, and either is non-zero, a copy of the key may be in use (§6.1.1). Passkeys synced between devices usually report 0 every time, so 0 and 0 is not flagged and the check cannot catch a clone of those.

Simplified: toy 64-bit RSA, one hash-then-sign message in place of CBOR and COSE, and a suffix match where browsers use the public suffix list so that co.uk can never be an RP ID.
