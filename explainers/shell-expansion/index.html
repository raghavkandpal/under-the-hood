Shell quoting and globs

The shell rewrites your command before the program runs, and the program only sees the result. Quotes decide what gets rewritten.

    How it works

    Splitting. With file="my notes.txt", rm $file hands rm two arguments, my and notes.txt, and rm "$file" hands it one. The shell replaces $file first, then cuts the result at spaces, tabs and newlines. Only text that came from an unquoted expansion is cut.

    Quotes. Single quotes change nothing: '$file' arrives as the literal text $file. Double quotes still expand $file but keep the value in one piece. Quoting also decides what happens to nothing: an unset variable unquoted vanishes, so echo $empty passes 0 arguments, while echo "$empty" passes 1 empty argument.

    Globs. An unquoted * or ? is matched against the directory, and the sorted matches replace the word. *.txt becomes a.txt b.txt: the file .hidden.txt is skipped, because a leading dot has to be typed. "*.txt" is never expanded. A pattern that matches nothing is passed as typed, so ls *.csv gets the literal *.csv, and ls complains about a file that does not exist. The program never sees a glob; it sees the list.

    Try it: run ls *. The directory holds a file named -l, so ls receives -l as one of its arguments and reads it as an option. ls ./* passes ./-l instead, which cannot be an option. The same trap hits rm *, which passes 4 names and keeps .hidden.txt.

    A toy: $name, both quotes, *, ? and a leading ./ only, one fixed directory, default word splitting. No braces, ~, backslashes, $(…) or other shells' options.
