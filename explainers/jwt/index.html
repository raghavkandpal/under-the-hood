JSON Web Tokens

After you log in, many APIs hand you a long string with two dots in it. It says who you are, anyone can read it, and the server never has to look anything up to trust it. One signature does all that work, and a few famous mistakes undo it.

How it works

  
Three parts. A JWT is a header, a payload and a signature, each base64url-encoded and joined with dots. The header names the algorithm. The payload holds claims: who the user is (sub), their role, when the token expires (exp). Base64 is an encoding, not encryption, so anyone holding the token can read every claim. Never put secrets in one.

  
The signature. With HS256 the server computes an HMAC-SHA256 of the first two parts using a key only it knows, and appends the result. To check a token, it recomputes the HMAC and compares. Change one character of the payload and the HMAC no longer matches; making a new one needs the key. So the server can trust the claims without a database lookup, which is why JWTs are popular between services. Asymmetric versions (RS256, ES256) sign with a private key, so other services can verify with the public key without being able to mint tokens; see digital signatures.

  
Try it. Log in, then edit the role. Then forge a token with alg none, first with the checkbox off, then on.

  
alg: none. The standard allows an unsigned token whose header says "alg": "none". Libraries that let the token's own header choose the algorithm accepted these forgeries as valid, a bug found in many of them in 2015. The fix is for the server to decide which algorithm it expects, and reject everything else.

  
You can't take one back. A signed token stays valid until it expires, even if the user logs out, changes their password or is banned, because nothing is looked up. So access tokens are kept short (minutes), paired with a refresh token the server can revoke, or checked against a deny-list, which brings back the lookup JWTs were meant to avoid.

  
Simplified: HS256 only, times in seconds from an arbitrary start, and the signature check is a plain string compare. Real code should compare in constant time; see timing attacks.
