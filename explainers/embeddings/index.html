Embeddings

To a model, a word is a list of numbers, a point in space, placed so that words with similar meanings sit close together. Search engines, recommendations and LLMs all run on this idea. Distance becomes meaning, and directions become relationships.

What's going on

Each word is a vector. Here every word has 16 numbers, one per readable feature (royal, female, animal, sweet…). Cosine similarity measures the angle between two vectors: 1 means the same direction, 0 means unrelated. It ignores length, so "a bit sweet" and "very sweet" can still point the same way.

Directions carry relationships. king − man leaves roughly "royalty", and adding woman lands near queen. The same offset that takes France to Paris takes Japan to Tokyo. Nobody programs these into a real model. They emerge from training on which words appear near each other.

Nearest neighbours are search. Semantic search turns a query into a vector and returns the documents whose vectors are closest, which is what the dimension sliders above do with words.

The map is a squashed shadow. To draw 16 dimensions on a flat screen, the plot uses PCA, which picks the two directions with the most spread. Nearby on the map usually means nearby in reality, but some neighbours get flattened together, so trust the similarity numbers over the picture.

Honest caveat: these vectors are hand-built so every dimension is readable. Real embeddings (word2vec, or the ones inside LLMs and search engines) have hundreds to thousands of dimensions learned from text, and no single dimension means anything you could name. They also absorb the biases of the text they're trained on.
