Gossip protocols

How do you tell 10,000 servers that one of them just died, with no central coordinator and with messages getting lost? Do what rumours do. Each node tells a couple of random others, who tell a couple more. News reaches everyone astonishingly fast, and no single failure can stop it.

How it works

Exponential spread. In round 1 one node knows. If each informed node tells one random peer, about 2 know after round 1, 4 after round 2, 8 after round 3. Doubling alone would reach n nodes in log₂ n rounds. The slow finish described below adds about ln n more, so going from a thousand nodes to a million adds only about 17 rounds. The curve is the S-shape of any epidemic: slow start, explosive middle, slow finish.

The slow finish is because, near the end, informed nodes keep picking peers who already know. Pull fixes it: every uninformed node asks a random peer “anything new?”, and when most know, almost every ask succeeds. Push-pull combines the fast start of push with the fast finish of pull.

Robust by redundancy. Nothing depends on any particular node or message. Drop 30% of messages, crash a fifth of the nodes, and the rumour still gets through to every live node a few rounds later. The price is duplicate messages: each node hears the news several times.

Used for cluster membership and failure detection (Cassandra, Consul's Serf, SWIM), spreading database updates between replicas (“anti-entropy” in Dynamo-style stores), Bitcoin transaction relay, and aggregating counts across huge systems. Related: CRDTs, which make merging the gossiped state safe.
