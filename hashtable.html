Hash tables

How does a dictionary find one key among a million without searching? It turns the key into a number, uses that number as an array index, and goes straight there. The interesting part is what happens when two keys want the same spot.

Type a key and insert it.

How it works

Hash, then mod. A hash function scrambles the key into a big number. Taking it modulo the array size gives the key's home slot. A good hash spreads keys evenly, so most slots hold zero or one key, and a lookup costs about one step however big the table gets.

Collisions are inevitable. With 23 keys and 365 slots there's already a 50% chance two share a slot (the birthday paradox). There are two classic fixes:

  • Separate chaining: each slot holds a small list. Colliding keys line up in it.
  • Linear probing: if your slot is taken, try the next, and the next. It's cache-friendly, but neighbouring keys pile into clusters (orange = not in its home slot). Deleting can't just empty a slot, or lookups for keys that probed past it would stop early, so it leaves a tombstone instead.

Load factor and resizing. As the table fills, collisions multiply, especially with probing. So when size / capacity crosses a threshold, the table doubles and re-inserts every key. A key's home slot depends on the capacity, so every key has to move. Doubling makes this rare enough that inserts stay cheap on average (amortised O(1)).

Try it: switch to first letter only, turn growth off, and add keys. Everything starting with the same letter lands in one slot, and the table degrades into a slow list. Switch back to FNV-1a and see the keys spread out.
